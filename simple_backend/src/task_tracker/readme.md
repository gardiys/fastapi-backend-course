Минус подхода хранения состояния в оперативной памяти: недолговременная память, при перезагрузке сервера состояние
потеряется. К тому же, если хранить много информации, то ОЗУ компа будет засоряться и производительность будет падать
С доступом админа все равно нельзя будет посмотреть содержимое, откатить или посмотреть историю.
Плохо масштабируется, для каждого приложения будет создаваться отдельная копия, и задача из одного не будет доступна
в другом. Подходит для очень мелких задач, так как способ простой и быстрый, для разработки более сложных приложений
лучше использовать базы данных.
--------------
Теперь я переписал программу, где таски сохраняются в json файле. Стало удобнее работать с интерефейсом, при перезагрузке сервера мои сохраненные
таски не исчезают, а подгружаются, но все еще есть пробелы. Если у меня будут тысячи задач, то таким файлом будет сложно манипулировать. Лучше 
всего хранить таски в базе данных или в облачном хранилище
---------------
Я подключился к JsonBin, теперь мои таски хранятся в облачном хранилище и вне зависимости от сбоев сервера, они сохранятся.
Так же я сделал свою программу более stateless, то есть независящей от предыдущих запросов, состояния не хранятся на сервере, вся 
информация находится в облаке, сервер лишь делает запрос по АПИ ключу и выводит информацию на экран.
-------------

будет брать нужную информацию с JSONBio при больших данных.
