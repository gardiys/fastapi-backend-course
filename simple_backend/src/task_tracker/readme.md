**Минусы подхода с хранением задач в оперативной памяти (списке Python)**

1. Потеря данных при завершении работы приложения - Все данные о задачах теряются при завершении работы программы, что делает этот метод ненадежным для долговременного хранения.
2. Отсутствие долговечности - Данные, которые хранятся в памяти, не могут быть восстановлены после перезапуска программы, что требует дополнительных мер для их сохранения (например, сохранение в файл или базу данных).
3. Ограничения по объему данных - Оперативная память ограничена, и с увеличением объема данных программа может столкнуться с нехваткой памяти.
4. Проблемы с многозадачностью и параллельностью - Когда приложение использует многозадачность или многопоточность, данные, хранящиеся в оперативной памяти, могут привести к проблемам с синхронизацией данных.
5. Медленное масштабирование - При росте данных приложение, использующее хранение в памяти, может столкнуться с трудностями масштабирования, что потребует перехода на более сложные механизмы хранения данных, такие как базы данных.

**Хранение информации о задачах в файле проекта. Формат json.**

Минусы:
1. Нет конкурентного доступа – Если несколько человек редактируют JSON-файл одновременно, могут быть сбои.
2. Ограниченная масштабируемость – Если задач становится слишком много, поиск и обработка становятся медленными.
3. Отсутствие индексации – В отличие от БД, JSON-файл не поддерживает быстрый поиск и фильтрацию.
4. Риск потери данных – Если файл поврежден или случайно удален, можно потерять все задачи.
5. Низкая безопасность – Файл легко изменить вручную или случайно удалить.

**Что улучшилось после перехода с оперативной памяти на файл проекта**
1. Сохранность данных - Ранее данные терялись при перезапуске программы. Теперь они сохраняются между сессиями.
2. Возможность совместной работы - Если проект в системе контроля версий (например, Git), разные пользователи могут видеть и редактировать задачи.
3. История изменений - JSON-файл можно отслеживать в Git, анализировать, возвращаться к старым версиям.
4. Удобство отладки – Можно вручную открыть файл, посмотреть, что там хранится, и при необходимости исправить.
5. Гибкость формата – JSON легко читать, экспортировать, конвертировать в другие форматы (CSV, XML).

**Нет, мы не избавились от хранения состояния, а просто изменили его способ хранения.**

**Кроме хранения в оперативной памяти и файле проекта, есть несколько других вариантов, каждый со своими плюсами и минусами.**

1. База данных (SQLite, PostgreSQL, MongoDB и др.)
🔹 Преимущества:
✅ Быстрый поиск, фильтрация, сортировка задач.
✅ Поддержка многопользовательской работы.
✅ Надежность: данные не теряются при сбоях.
✅ Масштабируемость – можно работать с тысячами задач.

🔻 Недостатки:
❌ Требует настройки и дополнительного кода для работы с БД.
❌ Сложнее, чем JSON-файл, если задач мало.
❌ Возможны накладные расходы на сервер (если БД в облаке).

🔹 Когда использовать?
Когда задач много, важен быстрый доступ и работа нескольких пользователей.

2. Облачное хранилище (Google Drive, Dropbox, Yandex Disk)
🔹 Преимущества:
✅ Автоматическая синхронизация между устройствами.
✅ Бэкап данных, защита от потери.
✅ Простая реализация (например, хранение JSON или CSV в облаке).

🔻 Недостатки:
❌ Зависимость от интернета.
❌ Ограниченная скорость доступа.
❌ Возможны проблемы с безопасностью, если данные не зашифрованы.

🔹 Когда использовать?
Когда нужен доступ с разных устройств, но нет желания развертывать сервер.

3. API и удаленные сервисы (Trello API, Google Tasks API, Jira и др.)
🔹 Преимущества:
✅ Нет необходимости разрабатывать свою систему хранения.
✅ Готовые инструменты для работы с задачами.
✅ Доступность с любого устройства.

🔻 Недостатки:
❌ Зависимость от стороннего сервиса.
❌ Возможны ограничения по API (лимиты на запросы).
❌ Проблемы с приватностью (данные хранятся у провайдера).

🔹 Когда использовать?
Когда не хочется разрабатывать собственную систему, а проще интегрироваться с готовым сервисом.

4. Кэш (Redis, Memcached)
🔹 Преимущества:
✅ Очень быстрое чтение/запись.
✅ Подходит для временного хранения часто используемых данных.

🔻 Недостатки:
❌ Данные не сохраняются при отключении сервера (если не настроено постоянное хранение).
❌ Обычно требует установки дополнительного ПО.

🔹 Когда использовать?
Если нужно временно хранить задачи для быстрого доступа (например, в веб-приложении).

5. Текстовый файл (CSV, TXT, XML)
🔹 Преимущества:
✅ Простота реализации.
✅ Легко переносить между системами.

🔻 Недостатки:
❌ Медленный поиск и фильтрация.
❌ Нет удобного механизма работы с большими объемами данных.

🔹 Когда использовать?
Если данных мало и важна простота.

Вывод
📌 Лучший вариант зависит от задачи:

Файл (JSON, CSV) – для небольших локальных проектов.

База данных (PostgreSQL, SQLite) – для сложных проектов с множеством задач.

Облако (Google Drive, Dropbox) – если нужен доступ с разных устройств.

API (Trello, Jira) – когда не хочется делать свое хранилище.

Кэш (Redis, Memcached) – если нужна максимальная скорость.
