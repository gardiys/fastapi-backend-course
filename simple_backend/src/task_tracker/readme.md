Основные минусы хранения в Python-списке:
1. Данные не сохраняются - исчезают после перезапуска сервера
2. Нет масштабируемости - каждый экземпляр сервера имеет свою копию данных
3. Ограниченный объём - много задач могут перегрузить память 
4. Нет надёжности - любой сбой = потеря всех данных 
5. Проблемы с параллелизмом - возможны конфликты при одновременных запросах

После замены хранения задач в оперативной памяти на файловое хранилище (JSON) мы получили следующие улучшения:
1. Сохранение данных между перезапусками - задачи теперь сохраняются после остановки сервера 
2. Возможность ручного управления - файл можно редактировать вручную для исправления данных
3. Простота резервного копирования - достаточно скопировать один файл 
4. Прозрачность данных - состояние системы легко проверить без доступа к серверу 
5. Снижение потребления памяти - данные загружаются только при необходимости

Проблема состояния гонки
1. Генерация ID - если два запроса придут одновременно, могут быть созданы задачи с одинаковыми ID
2. Обновление статусов - параллельное обновление одной и той же задачи может привести к потере изменений

Другие проблемы
1. Отсутствие транзакционности - нет механизма отката изменений при ошибках
2. Нет версионирования данных - невозможно отследить историю изменений задачи
