### Минусы хранения в оперативной памяти:
 **Потеря данных при перезагрузке** - все данные исчезают после остановки сервера
 **Невозможно масштабирование** - несколько экземпляров сервера будут иметь разные данные
 **Ограничение объема памяти** - большое количество задач может исчерпать память
 **Отсутствие persistence** - данные существуют только во время работы приложения

### Улучшения после перехода на файловое хранение:
- Данные сохраняются между перезапусками сервера
- Возможность бэкапа и восстановления данных
- Человекочитаемый формат (JSON)

### Избавились ли мы от хранения состояния?
**Нет.** Файловое хранилище все еще хранит состояние на сервере. Мы просто перенесли состояние из оперативной памяти в файловую систему.

### Альтернативные способы хранения:

1. **Базы данных (SQLite, PostgreSQL)**
   
2. **Облачные хранилища (JSONBin, MockAPI)**

3. **In-memory базы (Redis)**

## Состояние гонки (Race Condition)

### Проблемы в текущей реализации:
- Многопользовательский доступ может привести к конфликтам
- Одновременные запросы на запись могут перезаписывать друг друга
- Нет механизма блокировок при работе с файлом

### Решение проблемы:
1. **Блокировки файлов** - использовать file locking
2. **Базы данных** - перейти на SQLite с транзакциями  
3. **Очередь запросов** - обрабатывать запросы последовательно
4. **Версионирование** - добавлять версии к данным для разрешения конфликтов
