### Ответы на вопросы по ДЗ

#### Минусы хранения задач в оперативной памяти.
1. **Потеря данных** - данные в списке изменяются между запросами, при перезагрузке приложения все данные удаляются.
2. **Проблемы масштабируемости** - данные хранятся в конкретном экземпляре приложения. При необходимости развернуть несколько приложений например для быстродействия - приложения не будут "знать" о задачах в других экземплярах. Запросы могут выдавать ошибки при попытке получить данные . Нужно решать проблему синхронизации. 
3. **Максимальный риск состояния гонки** - т.к. нет встроенного механизма синхронизации (транзакции, блокировки) 

#### Что улучшилось после переноса задач в файл из списка python.
1. Теперь данные по задачам сохраняются между запусками приложения.
2. Стало больше вариантов для синхронизации. Файл можно передать, например на гитхаб.

#### Избавились ли мы таким способом от хранения состояния?
1. Не избавились, файл все еще хранится локально и доступ к нему только внутри приложения.

#### Где еще можно хранить задачи и какие есть преимущества и недостатки этих подходов?

1. **База данных (SQL)**
   - **Плюсы**:
     1. Данные сохраняются надёжно, не теряются при перезапуске.
     2. Есть механизм транзакций, блокировок — можно избежать конфликтов.
     3. Удобно делать сложные выборки, сортировку, фильтрацию.
     4. Подходит для масштабирования и продакшн-систем.
   - **Минусы**:
     1. Требуется установка и настройка сервера БД.
     2. Нельзя быстро протестировать без подготовки окружения.

2. **База данных (NoSQL)**
   - **Плюсы**:
     1. Можно хранить данные в виде JSON без схемы.
     2. Быстрый старт, особенно в облачных сервисах.
     3. Хорошо подходит под задачи с гибкой структурой.
   - **Минусы**:
     1. Сложнее контролировать целостность данных.
     2. Нет транзакций (или они ограничены).
     3. Тяжело поддерживать сложную бизнес-логику.

3. **Облачные JSON API (jsonbin.io, mockapi.io)**
   - **Плюсы**:
     1. Не требует установки базы данных.
     2. Удалённый доступ — можно сделать backend stateless.
     3. Быстрый способ сохранить JSON и получить его по API.
   - **Минусы**:
     1. Зависимость от стороннего сервиса.
     2. Есть ограничения по количеству запросов и размеру данных.
     3. Нет транзакций и защиты от одновременных записей.

#### Состояние гонки. Проблемы и решения.
1. Состояние гонки - если несколько клиентов делают запросы, то задачи могут затереться.
* Ввести систему версий jsonbin: перед сохранением проверять что версия не изменилась, если изменилась возвращать ошибку.
* Перейти на хранение задач в базе данных, чтобы можно использовать транзакции и блокировать задачудля других пользователей, пока она занята одним пользователем.
* Частичное обновление через PATH может немного снизить риск проблемы, но не существенно.
* Использовать git как систему версий.
2. Нет авторизации - единственный вариант сейчас работать с задачами это полный доступ.
3. Нет логгирования для отладки ошибок.
